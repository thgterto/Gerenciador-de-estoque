## 2025-02-20 - Leveraging Built-in String Optimizations over Date Object Caching
**Learning:** In `src/hooks/useInventoryFilters.ts`, the code originally attempted to optimize performance by instantiating a single `new Date()` outside the loop and passing it to `getItemStatus()`. However, `getItemStatus()` in `src/utils/businessRules.ts` has an explicit optimization to use ISO string date comparisons (`item.expiryDate < getTodayISO()`), which is approximately 5x faster than comparing `Date` objects (`new Date(item.expiryDate) < now`). By explicitly passing the `Date` object to the function, the caller was inadvertently forcing the *slow path* (`new Date(item.expiryDate)`) to be evaluated for every item, completely bypassing the string comparison optimization.
**Action:** When a helper function provides an optimized fast-path (like string comparison caching), avoid pre-optimizing the inputs (like hoisting object creations) if it forces the function to fallback to a slower, legacy behavior.
