## 2025-02-12 - Date processing optimization
**Learning:** Parsing full ISO 8601 strings to `Date` objects inside tight analytics loops in React creates significant Garbage Collection and CPU overhead on large local datasets. However, using string comparisons (like `startsWith` or `h.date < window`) on UTC ISO strings causes critical timezone regressions because dashboards evaluate "today" or "this month" based on the user's local timezone.
**Action:** When filtering dates by ranges, use `Date.parse(h.date)` instead of `new Date(h.date)` for ~3x faster timestamp extraction that preserves timezone safety perfectly. When mapping dates to local strings or buckets (year/month), cache the parsed results `Map<string, { toDateString, year, month }>` keyed by the exact ISO string, as many analytics events share identical timestamps (e.g. bulk uploads) or exact minute signatures.
